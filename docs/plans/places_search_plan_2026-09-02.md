## 2 · Дизайнът (пренесен от 22.08, D1–D9; промените са отбелязани)

- **D1 Payload:** `data/hotels.json` = байт-идентично копие на доставката
  (sha закован на **`17800b5d…`**, 226), lazy fetch при първи фокус в собствен
  Cache-namespace, fail-soft (не зареди ли → адресите работят както днес).
- **D2 Валидиране при зареждане, fail-closed към отсъствие:** `_meta.count
  == hotels.length == 226`; **12** ключа точно; bbox 43.00–43.45/27.60–28.15;
  сканиране за кадастрални низове.
- **D3 Матчинг:** клиентски, върху 226 записа; токени от `name` +
  `old_names` + `zone` + `kind`, през СЪЩИТЕ `norm()`/`skel()`/`matchKindSet`
  като адресите (недокоснати); exact > prefix > fuzzy (cap 1–2); всички
  токени на заявката трябва да съвпаднат. **Ново:** приемният тест G4 включва
  „адмирал" → **три** реда (вкл. АМИРАЛ през fuzzy), „адмирал златни" → един.
- **D4 Рендериране:** отделен блок ПОД точните адресни редове със собствен
  групов хедър (`asr-group-header` вече съществува, ред 1083/5341), чип
  `хотел`, зоната на реда (три Адмирала = три реда с три зони), старо име и
  „бивш" по подписаната формулировка (§7).
- **D5 Избор:** както при адрес — `anchorHydrantsAt` (хидрантите се
  пренареждат около хотела — оперативната печалба), същият маркер-слот,
  оранжев пин, zoom ≥ 17, попъп с име/вид/★/легла/зона/източник/навигация.
- **D6 Флаг:** `HOTELS_SEARCH_ENABLED` (kill-switch); препоръка `true`.
- **D7 Атрибуция:** README (BG+EN) с реда `_meta.licence` ДОСЛОВНО +
  източник на всеки запис в попъпа (НТР / КАИС адресно поле / координати
  КАИС Отворени данни). Без назован лиценз (ФАЗА_0).
- **D8 Bundle-тест:** `tests/test_hotels_public_bundle.py` — sha/байтове/
  gzip, 226, 12 ключа, енумерации на вид/източник/статус, bbox, забранени
  низове, лицензният ред байт-равен, mojibake 0.
- **D9 Недокоснати поименно:** `search_index.json`, `address_rows.json`,
