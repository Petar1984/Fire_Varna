# ADR 007 — The address path and its delivery: a signed write-set, a differential G3 and a kill switch

**Status:** Proposed — awaiting Petar (Gate 1). · **Date:** 2026-09-03. · **Amends:** ADR 006 D4 and D12 (the named untouchables) for one enumerated write-set only; everything else in 006 stays in force. · **Plan:** `docs/plans/recommendations_2026-09-03.md` §3 (ЛОТ 2 „Адресният път и доставката му"), decisions 3, 5, 15, 16, 17, 18, 19 of `docs/audits/ОДИТ_03.09_система.md` §7. · **Attacks that shaped it:** Sol (`scratch/audit_2026-09-03/sol_verdict_2.md` §4–§6 — the contract below is his, accepted almost verbatim), the judge panel (`judges_summary.txt`, cost/risk lens), Kimi (data lens on the labels).

## Context

The system audit of 03.09 measured the address path — the search every call goes through — for the first time (`ОДИТ_03.09_система.md` §10.4): over a deterministic sample of 3 470 queries against the live engine, a plain address (`kind:address`) reaches the exact record in the top 8 only 16.8 % of the time, while the *label* is found 94.1 % of the time. The cause is not the matcher: 71 100 of 86 232 records (82.5 %) share their label with another record, the first row is another pin under the same text in 75 % of the cases (median 461 m away, p90 2 710 m), and `dedupeDisplayRows` folds equal labels after the cut to 8. Three more facts belong to the same path: 31 916 records (13 683 of the 25 343 unique labels, 54 %) reach the firefighter in Latin because the build writes the cleaned `addr_key` as `label` and the UI prefers `label` over the Cyrillic `address_rows` text; the type word the app itself prints („кв.", „ж.к.") throws the target out of the list (removing it from the query: +7.8 points @1 over 694 labels, 84 improved / 4 worse); and the address renderer has no „…и още N" tail, so 8 of 984 equal candidates look like the complete answer. ADR 006 D12 forbids every function of `initAddressSearch` and pins `data/search_index.json` byte-for-byte; G3 is defined as byte-equality of the address-search probe corpus. None of the fixes above is possible under that contract — and Sol showed that even the „one line in the build" for the Cyrillic labels changes the pinned `search_index.json`, so the amendment is a precondition for the *data* fix too, not only for the code.

## Decision

**D1 — Scope of the amendment.** D4/D12 of ADR 006 remain in force outside the write-set enumerated here. The amendment enters *before* the first change of ЛОТ 2 (data or code). Nothing else in 006 changes: the places IIFE keeps its own contract, gates and kill switch.

**D2 — Data write-set (Varna_buildings → Fire_Varna).** `js/build_fire_varna_search_index.mjs`, `js/test_fire_varna_publish_gate.mjs` and the generated `Fire_Varna/data/search_index.json` (with a new `generation_manifest.json`). Untouchable: `data/address_rows.json`, `sw.js`, `worker/`, the hydrant / report / compass paths, `data/approx_addresses_v1.json`.

**D3 — Address write-set (Fire_Varna `index.html`, inside `initAddressSearch`).** Only: the flag and its helpers, `dedupeDisplayRows`, `runGeocoderSearch` (the dedupe-before-cut and the query dispatch), `buildExactItem`, `renderResults`, `renderCombined`, and one named renderer for the block warning. Pinned (still forbidden): the scorer and comparator, `selectResult`, click/Enter navigation, the detail fetch, the exact-coordinate path, every other function and every `asr-*` / `search-pin*` selector.

**D4 — Kill switch `ADDRESS_PATH_V2`.** A selector at each of the use sites in D3 — never an early `return` at the top of the IIFE (that would remove the address search). With `ADDRESS_PATH_V2 = false` the DOM, the backing identity, the selection and the failure/race behaviour are byte-equal to the signed post-ЛОТ-2 baseline; with `true` only the differential G3 differences enumerated in D6 are allowed — any other difference is STOP. Precedent: ADR 006 D11.

**D5 — The five changes and their exact rules.**
1. *Physical-building group key* (decision 18): the delivery carries `pb = HMAC-SHA256(secret, "vpb1|" + private_pbid)` rendered as `b` + 16 lowercase hex — a separate domain from `g`, never a raw or bare-hashed cadastral id (the raw `physical_building_id` is `min(member cadnum)`); a public-safe representative map `pbr: pb → _ord` (or a marker on the representative row); `PB_KEY_RE` + type/shape check + dotted-cadnum poison fixtures in the publish gate; snapshot gate (today 483 stamped rows / 198 groups: 420 `mf` + 63 `address`, never `en` or parcel); two builds with the same inputs are byte-identical; churn gate over the private sorted member sets — split / merge / migration / representative change is STOP until a signed migration manifest. `PRIVATE_KEYS` and `FORBIDDEN_SUBSTRINGS` stay untouched; only `pb` (and `pbr`) enter `ALLOWED_ENTRY_KEYS`.
2. *Cyrillic labels* (decision 5): a late selective pass in the build after F3 (lines ~806 and ~826): emit `display_id` wherever `address_rows` has the row, and drop `label` only where the Cyrillic row is at least as informative — with an exact old→new ledger, the F3 block labels (196 rows) kept, and a quality gate that fails on empty / letterless / ≤3-character / less-informative labels (Sol measured 11 813 shorter and 17 letterless results under a naive flip — those keep `label`). „Адрес:" prefixes (522 labels) are cleaned in the same build. The UI preference in `baseAddressLabel` follows the data (step 2 before step 1 where `display_id` exists).
3. *Dedupe before the cut and the tail* (decisions 3, 17): `R` = the full ranked set after physical/block grouping; `D = dedupeV2(R)` with the key `norm(label) + '||' + g + '||' + pin(5 dp)`; `V = D.slice(0, limit)`; `N = |D| − |V|` rendered as „…и още N" — a tail node without `data-idx`, not selectable, not in `currentResults`.
4. *Type word as a second-pass fallback* (decision 15): only on the raw query, only when the legacy path has no clean all-token hit, only for the enumerated set „кв./ж.к./к.к./в.з." + „Адрес:" + „·" — never „ул./бул./пл." (38 street names exist both as „ул" and „бул"), never on the index or the label („кв. Чайка" and „к.к. Чайка" stay distinct).
5. *Differentiator* (decision 16): each row may carry a deterministic meta text „distance · bearing" from the operational anchor `lastFix` (GPS fix, manual pin, or the previously selected address); no anchor → no suffix; `map.getCenter()` is never a fallback; rank, identity, click, Enter and navigation do not change. Plus one named renderer: when a block has sections but the requested entrance is not labelled, the row says „входовете на този блок не са етикетирани" instead of silently returning the block pin (decision 19).

**D6 — G3 becomes a differential replay.** The corpus: fixed payload hashes, browser/viewport, cache state, a fixed WGS84 anchor injected before every headless query (and a separate no-fix series expecting zero suffixes), the nine original G3 queries, the 3 470-row engine corpus of the audit, and targeted series (`pb` groups, >200 m label groups, Чайка/к.к. Чайка, bare block + entrance, no-GPS). The proof: full `outerHTML` + backing identity (pin, `g`, nav coordinates, popup title, selection side effects) for every visible row. Allowed differences, and only these: (18) folding of members of a signed `pb` group to the signed representative; (3) the same label/g appearing at a different exact pin, relative order of old identities preserved; (15) only the signed diff when the fallback fires; (16) only the deterministic meta text; (17) `N = |D| − |V|`. Everything else is STOP.

**D7 — Order inside the lot.** ADR (this document) → the build (2, 1 with the privacy contract, the manifest, the publish gate with the new readability and privacy checks) → the client (4 → 3 → 5 → 4 with the flag) → the harness before/after (`kind:address` recall @8 from 16.8 % upward with 0 worsened labels; the type-word A/B re-measured after the Cyrillic labels, because the 694-label sample will grow by ~39 000 rows) → audit → Gate 2.

## Consequences

- The address path gets, for the first time, a kill switch and a differential contract; the price is one signature on this ADR and the loss of byte-equality as the definition of G3.
- The delivery grows by `pb`/`pbr` (~200 KB raw) and loses ~900 KB of Latin labels where the Cyrillic row replaces them; the gzip gain is small (~20 KB, Sol) — the point is readability, not bytes.
- Every step is reversible: the flag for the client, the manifest for the data, `git revert` per commit.

## Rollback

`ADDRESS_PATH_V2 = false` restores the signed post-ЛОТ-2 baseline without a revert; the data change reverts with the commit that carried the new `search_index.json` (the old manifest is kept in `Varna_buildings/output/fire_varna_baseline/`).

## Obligations

1. Sign this ADR before any file in D2/D3 is touched (Petar, Gate 1).
2. Re-measure decision 15 after the Cyrillic labels; re-measure the 545 label groups >200 m after `pb` (Sol: `pb` alone resolves none of them — 3 is evaluated independently).
3. The frozen G3 baseline (`scratch/places_search/probe_out/before.json`) is re-frozen once, in its own commit, after the build lands and before the client changes.
