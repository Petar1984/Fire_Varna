## 2 · Какво точно проверява `src/verify_web_rows.py` (канал 4)

Ред по ред, всеки провал → `_board` с причина, не в `places`:
1. няма URL → борд; 2. `PERSON_RE` (`ЕТ|Е.Т.|д-р|Д-р|ДР.|адв.|Адв.|нотариус`) в името → борд (K4.1: **няма изключение**); 3. не е `https` → борд; 4. хостът е в `DENY_DOMAINS` (**43 домейна**, `verify_web_rows.py:96-105`) — съвпадението е по цели етикети, не подниз; 5. страницата не се отвори → борд; 6. **името не се среща в текста на страницата** → борд; 7. PII в името от страницата → борд; 8. **адресът на сградата не е на страницата** ИЛИ страницата е списъчна (`LISTING_HOSTS` = `regtourist.uslugi.io`, `uslugi.io`; или ≥ 5 блока „обл … общ …", `LISTING_ADDR_RECORDS = 5`) → борд с причина.
Кешът се записва **изчистен** (телефони, e-mail-и, кадастрален формат маскирани) ПРЕДИ да докосне диска; суров HTML не се пази; 1,1 s/заявка; UA `varna_3d-place-verifier/1.0`.
Финални гейтове: уникални `id` · `name_src`+URL · `kind` · `0 ≤ i < 80497` · кутията · 0 кадастрални · 0 PII · 0 лични имена · връзка→място · K6.2 ≥ 5 от 20. **Резултат: 20 реда на Сол → 6 проверени, 14 на борда.**

`DENY_DOMAINS` включва и `openstreetmap.org`, `wikipedia.org`, `wikidata.org` — П3 не може да краде име от канал, който си има свой път. Това е правилно построено.

## 6 · Какво НЕ можах да измеря (и с коя команда се затваря)

Дедуп по **име + координата ≤ 60 m** срещу `data/fire_varna_places.json` (150) и `data/fire_varna_hotels.json` (225) — иска изпълнение на код, а тази роля няма шел. 10-минутен лот:
```
PYTHONIOENCODING=utf-8 python - <<'PY'
import json, math
def L(p): return json.load(open(p, encoding='utf-8'))
tgt = [(r['name'], r['lat'], r['lon'], f) for f, k in
       (('fire_varna_places.json','places'), ('fire_varna_hotels.json','hotels'))
       for r in L('data/'+f).get(k, L('data/'+f).get('places', []))]
for src in ('raw_public_osm_places','raw_ntr_zhr_places','raw_wikidata_places','raw_web_places'):
    P = L(f'data/{src}.json')['places']
    n = sum(1 for p in P for (nm, la, lo, _) in tgt
            if math.hypot((p['lat']-la)*111320, (p['lon']-lo)*81000) <= 60)
    print(src, len(P), '→ двойки ≤60 m:', n)
PY
```
Хипотезата ми (по конструкцията на каналите и по структурната проверка в §4) е **близо до нула нови места**, но това е хипотеза, не мярка.

## 4 · Дефекти и разминавания, които намерих в самите файлове

1. **Схемна дрейф: `raw_web_places.json` няма секция `_extra` на ниво документ.** Другите три я имат (`rg -n '^ "[a-zA-Z_]+"'`: OSM → ред 43081; Wikidata → 5523; НТР → 17147). Web файлът държи `_extra` **вътре във всяко място**. Резултатът е видим в доставения CSV: шестте web реда излизат с **празни `group`, `search`, `d_m`** — напр. `9660;…;vn-web-mebelilazur.bg-9660;Мебелна палата Лазур;venue;магазин;;;[];официален сайт mebelilazur.bg;…;;0.6;…`. Затова `rg -c ';True;'` = 422 = OSM 217 + Wikidata 24 + НТР 181 + **web 0**, макар че в суровия файл „Старата къща" е `search: true`.
2. **„Официален сайт", който е регистър.** `vn-web-regtourist.uslugi.io-56236` носи `name_src = "официален сайт regtourist.uslugi.io · …"`, но `regtourist.uslugi.io` **е НТР** — т.е. същият извор като канал А3, етикетиран като П3. Редът е `listing_page: true` + `needs_eye: true` и въпреки това е в `places`. Причината е документирана честно в кода: `verify_web_rows.py:126-132` — `BOARD_EVERY_LISTING_ROW = False`, с коментар „*строгото четене на амандамента дава 5 места / 15 борд; числата на архитекта (6/14) са четенето отдолу. Една дума го обръща*". **Това е решение за Петър, не бъг** — но 6-те стават 5, ако каже строгото четене.
3. **Един обект = две места.** Мебелна палата Лазур (тела 9660 и 9661) е записана като два `id`-та с едно име. По Р4 това е едно venue с две `relations`.
4. **Дублирано име в НТР на едно тяло.** `i=4342`: `vn-ntr-zhr-9508` „Аква" (Бар) и `vn-ntr-zhr-9509` „Аква" (Ресторант) — два сертификата на един обект. Регистърът ги брои като два реда; картата ще ги покаже като два пина на 0 m.
5. **Суровите файлове нямат свой QA гейт в репото.** `src/qa_places.py` съди само `data/places.json` (ред 30). Проверките на А1/А3/А4/А5 са тичали **вътре в apply-скриптовете**; няма `qa_raw_*.py`, който да ги пресъди утре. (`qa_no_cad_ids.py` ги покрива, но само за кадастрални идентификатори.)
