# Факти за поправката на спящия SW — измерени, с цитати (11.08.2026)

Контекст за сесията „Fix dormant SW cache flaws before basemap flag flip".
Събрани в друга сесия (Kimi одит + Sol проучване), проверени срещу кода.
Тези факти ОГРАНИЧАВАТ дизайна на поправката — не са предложения.

## Измерено за GitHub Pages (Sol, urlscan trace 08.03.2026 и 20.05.2026)

- `Cache-Control: max-age=600` и за HTML, и за JS. Без `public`, без
  `immutable`, без `must-revalidate`. Слаби ETag-ове (`W/"…"`), различни на
  ресурс; `Vary: Accept-Encoding`.
- 304 ревалидацията работи нормално (мерена); `Age` участва в сметката.
- max-age=600 е дългогодишно измерено поведение, но НЕ е официално
  гарантирана политика на Pages — дизайнът да не разчита, че никога няма да
  се промени.

## Спецификация на SW update (W3C CR Draft 04.08.2026)

- Update = **byte-compare само на тялото на `sw.js`** (+ importScripts
  графа). Промяна на `index.html` НИКОГА не предизвиква нов install. Смяна
  само на хедъри също не.
- `updateViaCache` управлява HTTP кеша за worker скриптовете, не Cache API.
  Default `imports`: главният `sw.js` е винаги с ревалидация.
- Регистрация по-стара от 86 400 s → принудително `no-cache` за update
  проверката.
- Cache API записите не изтичат сами — мени ги само код (`put`/`delete`)
  или евикция на origin storage.
- Chrome 68+: update проверката на `sw.js` заобикаля fresh HTTP кеша.

## Следствия за трите дефекта

1. **Замразената обвивка**: единственият писач на `CACHE_CORE` е `install`,
   а `install` тича само при промяна на байтовете на `sw.js`. Поправка,
   която не добавя писач на index.html при успешна навигация (или не
   отвързва CACHE_CORE от BASEMAP_VERSION), не решава дефекта.
2. **Изтритият пакет**: `activate` трие по суфикс на версията — миграция или
   изрично съгласие преди изтриване; старият пакет да не пада, преди новият
   да е потвърдено свален.
3. **10-минутният прозорец**: реален заради мереното `max-age=600` на HTML +
   Chrome bypass за `sw.js`. Смекчение: старите версионирани активи да
   останат на сървъра поне един деплой (виж и клас дефекта по-долу).

## Два документирани капана при версионирани имена (за дизайна на fix-а)

- **Cloudflare (03.07.2026):** HTML от версия A иска актив на A, а деплой B
  вече не го съдържа → 404. Старите версии се пазят в дървото един деплой.
- **AWS/Cloudflare:** query-string версиониране (`?v=`) е ненадеждно през
  посредници — само версия в името на файла.
